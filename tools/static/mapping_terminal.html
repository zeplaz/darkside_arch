Item writes are mapped from the command line

            
These are the RAM sites ds_client writes when ReceivedItems arrive. A memory diff cannot find them reliably, so this page only shows their status. Items received for an unmapped row (offset 0x0) wait and are written once the row is mapped.

HUD numbers (souls, counts)

            
python -m tools scan --item "Beholder Key"

            
--item is the row's label; the scan saves onto that row and enables it. Heap addresses become a pointer chain automatically. New item: copy a template row in targets.json with the exact Items.py name as label. Remove: "enabled": false or delete the row.

HOW THIS WORKS

      
    

    
This page finds the RAM byte behind each Archipelago location and saves it to targets.json. It reads the game but never writes to it, and it never connects to the AP server — the runtime is python -m ds_client --connect HOST:PORT --slot NAME.

    

      

        
CAPTURE A CHEST

        
    
          
  1. Launch Darksiders Warmastered. GAME turns green within a second.
    2. 
          
  2. Walk to a chest that is still closed. Pick its exact name on the left.
    3. 
          
  3. Baseline — stand still.
    4. 
          
  4. Open the chest in-game, then Diff.
    5. 
          
  5. One candidate → Save. Several → click the right row, or Diff again. None → the flag is probably on the heap.
    6. 
        

        
After saving, the location appears under LIVE VALUES and its value updates as you play — that is your check that the offset is right.

        
STATUS BAR

        
    
          
  • GAME — attached, pid, module base (ASLR; never stored).
    • 
          
  • SERVER — this page's backend. Red = restart python -m tools dashboard.
    • 
          
  • CHECKS — locations with a real offset. 0 means a seed cannot report anything yet.
    • 
          
  • ITEMS — inventory / goal rows with a real offset.
    • 
          
  • AP — slot@uri from ap_config.json.
    • 
        

      

      

        
FIX OR REMOVE A ROW

        
    
          
  • Wrong offset: capture the same location again — Save overwrites it.
    • 
          
  • Skip it: set "enabled": false in targets.json.
    • 
          
  • Drop it: delete the object. Don't keep offsets you no longer trust.
    • 
          
  • Labels must match Locations.py exactly. Refresh the list with python -m tools sync-world.
    • 
        

        
CLI EQUIVALENTS

        
    
          
  • python -m tools capture --region Crossroads — same flow in a terminal; both save to the same row.
    • 
          
  • python -m tools scan --item NAME — HUD numbers / item counts (default: souls).
    • 
          
  • python -m ds_client --no-ap — log changes to SQLite; they show in ACTIVITY.
    •
